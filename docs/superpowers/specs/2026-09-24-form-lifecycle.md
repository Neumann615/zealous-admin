# 表单生命周期与宽松契约改造记录

## 背景

参考 `form-manage.web` 与表单服务 OpenAPI 的表单定义域设计，但不接入远端服务，也不引入流程、子模板或阶段权限。当前项目的核心缺口是：单行可变 Schema、无版本历史、草稿可提交、历史数据按最新结构回显、删除表单会级联硬删数据。

## 落地内容

- 新增 `za_form_version`，承载草稿、发布历史、当前版、乐观锁与字段契约。
- `za_form` 增加 `form_key`、`current_version_id`、`deleted_at`，保留稳定表单身份。
- `za_form_data` 增加 `form_version_id`，新提交严格关联提交时版本。
- 新增草稿派生、发布、退役、恢复、版本列表接口；Schema 保存仅允许草稿并携带乐观锁。
- 删除改为软删除：纯草稿删除表单，已发布表的删除只放弃草稿，发布表单必须退役。
- 服务端新增宽松字段契约：只校验 JSON 树、节点 id、字段路径与基础提交形态；设计器扩展配置原样保留。
- 新填写仅允许发布版；按 `dataId` 回显时使用提交时版本。
- 元数据引用扫描排除已软删除表单。
- 前端最小适配：设计页自动派生草稿并携带乐观锁，列表操作切换为发布 / 退役 / 恢复 / 放弃草稿。
- 数据页版本化：列表与导出支持 `versionId` 筛选，动态列按所选版本生成，详情抽屉按每条记录提交时版本渲染；CSV 导出改为分页聚合并增加公式注入防护。
- 附件闭环：新增 `za_form_file` BLOB 主存、授权上传 / 下载接口与设计器宿主文件传输注入；提交值保存 `objectId + 文件元数据`，单文件限制 10MB。

## 验证

- 新增 `service/src/modules/form/formFile.service.test.ts` 与渲染器上传用例，覆盖文件存取、尺寸 / 标识校验和提交元数据化。

- E2E：元数据引用保护、权限下沉通过。
